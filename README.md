# Виселица Онлайн

Браузерная «Виселица» с настоящим мультиплеером через WebSocket (Socket.IO).
Два игрока из разных сетей играют в одной комнате в реальном времени. Есть режим против компьютера и подбор случайного соперника. **Базы данных нет** — комнаты живут в оперативной памяти сервера, регистрация не нужна.

## Структура проекта

```
hangman-online/
├── package.json        зависимости и скрипты (start, dev, test)
├── server.js           Express + Socket.IO: комнаты, ходы, компьютер, переподключение
├── words.js            словари RU/EN по категориям
├── public/
│   ├── index.html      разметка (главный и игровой экраны)
│   ├── style.css       тёмная тема, градиенты, анимации, адаптив
│   └── app.js          клиент: Socket.IO, отрисовка, звук, RU/EN, конфетти
├── test/e2e.js         интеграционный тест (настоящие клиенты Socket.IO)
├── Dockerfile
├── render.yaml         готовая конфигурация для Render.com
└── README.md
```

## Запуск локально

Нужен Node.js 18 или новее.

```bash
npm install
npm start
```

Откройте http://localhost:3000. Чтобы проверить мультиплеер, откройте игру в двух вкладках (у каждой вкладки своя сессия), создайте комнату в одной и войдите по коду или ссылке в другой.

Проверка автотестом (двое игроков, отключение, компьютер, подбор соперника):

```bash
npm test
```

Игра по домашней сети: откройте `http://<IP-вашего-компьютера>:3000` с телефона в той же Wi-Fi сети.

## Быстро поиграть с другом, не публикуя сайт

Запустите `npm start`, затем в другом терминале откройте туннель:

```bash
npx localtunnel --port 3000
# или: ngrok http 3000
# или: cloudflared tunnel --url http://localhost:3000
```

Отправьте другу выданную https-ссылку. Пока ваш компьютер и туннель работают, игра доступна из интернета.

## Публикация в интернете

Подойдёт любой хостинг с Node.js и поддержкой WebSocket. Команда сборки: `npm install`, команда запуска: `npm start`. Порт берётся из переменной `PORT` (хостинг задаёт её сам).

> **Важно:** комнаты хранятся в памяти одного процесса, поэтому запускайте **ровно один экземпляр** приложения (не включайте автомасштабирование на несколько инстансов). При перезапуске сервера комнаты исчезают — это ожидаемо.

### Вариант 0: страница на GitHub Pages + сервер на Render

GitHub Pages раздаёт только статические файлы и не умеет запускать Node.js, поэтому игра делится на две части: сайт (`public/`) на GitHub Pages, а сервер на Render. Пошагово:

1. **Репозиторий.** Создайте на github.com пустой репозиторий (например `hangman-online`) и загрузите в него проект:
   ```bash
   git init -b main
   git add .
   git commit -m "Hangman Online"
   git remote add origin https://github.com/<ваш-логин>/hangman-online.git
   git push -u origin main
   ```
2. **Сервер.** На render.com: New → Web Service → выберите этот репозиторий (Build: `npm install`, Start: `npm start`). В разделе Environment добавьте `CORS_ORIGIN` = `https://<ваш-логин>.github.io`. Получите адрес вида `https://hangman-online.onrender.com`.
3. **Адрес сервера в клиенте.** В файле `public/config.js` впишите этот адрес:
   ```js
   window.HANGMAN_SERVER = 'https://hangman-online.onrender.com';
   ```
   и сделайте `git commit -am "server url" && git push`.
4. **Pages.** В репозитории: Settings → Pages → Source: **GitHub Actions**. Workflow `.github/workflows/pages.yml` опубликует папку `public/` после каждого push в `main`.
5. Игра откроется по адресу `https://<ваш-логин>.github.io/hangman-online/`. Ссылки-приглашения тоже будут вести на этот адрес.

Бесплатный Render «засыпает» после простоя: первое подключение может занять около минуты, пока сервер проснётся.

### Вариант 1: Render.com (бесплатно)

1. Загрузите папку проекта в репозиторий GitHub.
2. На render.com выберите **New → Web Service** и подключите репозиторий (файл `render.yaml` уже настроен; можно использовать **New → Blueprint**).
3. Build Command: `npm install`, Start Command: `npm start`.
4. Через пару минут получите адрес вида `https://hangman-online.onrender.com` — его и отправляйте другу.

На бесплатном тарифе сервис «засыпает» после простоя, первый заход может занять около минуты.

### Вариант 2: Railway / Fly.io / Koyeb

Создайте проект из репозитория GitHub. Платформа сама определит Node.js, выполнит `npm install` и `npm start`. Включите публичный домен (Generate Domain). WebSocket работает без дополнительных настроек.

```bash
docker build -t hangman-online .

```

### Вариант 4: свой VPS (Ubuntu) с Nginx и HTTPS

```bash
git clone <ваш-репозиторий> && cd hangman-online
npm install --omit=dev
sudo npm i -g pm2
pm2 start server.js --name hangman && pm2 save && pm2 startup
```

Конфигурация Nginx (важны заголовки для WebSocket):

```nginx
server {
    server_name game.example.com;

    location / {
        proxy_pass http://127.0.0.1:3000;
        proxy_http_version 1.1;
        proxy_set_header Upgrade $http_upgrade;
        proxy_set_header Connection "upgrade";
        proxy_set_header Host $host;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_read_timeout 120s;
    }
}
```

HTTPS: `sudo certbot --nginx -d game.example.com`.

### Переменные окружения (необязательно)

| Переменная | Назначение | По умолчанию |
|---|---|---|
| `PORT` | порт сервера | `3000` |
| `CORS_ORIGIN` | список разрешённых источников через запятую (нужно, только если клиент открыт с другого домена) | выключено |
| `RECONNECT_GRACE_MS` | сколько ждать вернувшегося игрока, мс | `60000` |

## Как играть

1. Введите имя. Язык интерфейса (RU/EN) задаёт и язык слов.
2. **Играть онлайн** — поиск случайного соперника. **Создать комнату** — получите ссылку и код 5 символов, скопируйте ссылку одним нажатием и отправьте другу. **Присоединиться** — введите код. **Играть с компьютером** — одиночный режим.
3. Игроки называют буквы по очереди (можно и с физической клавиатуры). Верная буква: 10 очков за каждое вхождение. Неверная: минус одна из 6 общих попыток.
4. Кто открыл последнюю букву, получает бонус 20 очков. Раунд выигрывает тот, у кого больше очков за раунд. Если попытки кончились — побеждает виселица. Затем «Новая игра» запускает следующий раунд, счёт сохраняется, первый ход чередуется.

## Как устроен мультиплеер

- **Сервер — единственный источник правды.** Клиент отправляет только `game:guess {letter}`; очередь хода, допустимость буквы, подсчёт очков и конец раунда проверяет сервер.
- **Слово не уходит клиентам до конца раунда.** Клиент получает только маску (`null` вместо закрытых букв); слово приходит вместе с результатом раунда.
- **Статусы игроков:** «В сети», «Подключение…» (ожидание соперника или собственное переподключение), «Отключился» (с обратным отсчётом).
- **Обрыв связи:** игрок, потерявший соединение, 60 секунд может вернуться (в том числе после обновления страницы — токен хранится в `sessionStorage`). Если не вернулся, его слот освобождается, а комната ждёт нового игрока. Выход кнопкой освобождает слот сразу.
- **Компьютер** выбирает буквы, фильтруя словарь по уже открытым буквам, и не видит загаданного слова.
- **Защита от злоупотреблений:** ограничение частоты событий, лимит размера сообщений, проверка всех входных данных, не более двух игроков в комнате, автоматическая очистка забытых комнат.

## События Socket.IO

Клиент → сервер: `room:create`, `room:join`, `room:rejoin`, `room:leave`, `cpu:start`, `match:find`, `match:cancel`, `game:guess`, `game:next`.
Сервер → клиент: `state` (полное состояние для конкретного игрока), `notice` (вошёл / вышел / отключился), `match:found`, `kicked`.
